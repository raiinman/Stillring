# 67 — Gate 3 Cantor Key + Anchor Line Synthesis Addendum

**Status:** LOCKED — scheduled-run owner delegation  
**Issue:** #115  
**Decision:** #8 — combination / synthesis rules

## Decision

Cantor Key and Anchor Line combine through **shared world state**, not a special combo mode.

Cantor measures and applies learned diagnostic procedures to resonant relationships. Anchor changes physical load. A synthesis interaction is valid when one system's honest state change creates new information or eligibility for the other.

> **Cantor explains the relationship. Anchor changes the load. Neither pretends to be the other.**

## No combo button

There is no generic `Cantor + Anchor` action, fusion meter, special combined reticle, or context-sensitive super-tool state.

The player continues to use the ordinary Cantor and Anchor inputs already locked.

Synthesis emerges from sequence and state:
1. diagnose;
2. physically change something;
3. observe the changed relation;
4. apply another known procedure if useful.

The order may reverse when the world supports it: Anchor can expose or reconfigure a physically hidden relationship that Cantor can then measure.

## Shared-state contract

Systems compose only through explicit semantic world data.

Representative shared facts may include:
- a load is currently braced/unbraced;
- a component is under tension/slack;
- a structure is inside/outside a known safe tolerance;
- a local relation is stable/drifting/conflicting;
- a previously occluded maintenance surface is now physically exposed;
- a known Cantor procedure has established a temporary local operating relation;
- a mechanism has changed constraint/alignment state.

Cantor may read facts it is legitimately capable of measuring. Anchor may act only on load points it is physically compatible with. Neither system gets a hidden exception because the designer wants a combination puzzle.

## Legitimate synthesis families

### Diagnose → manipulate
Cantor identifies the relevant relationship, but not the solution gesture.

Example pattern:
- Cantor shows that a visible brace is carrying abnormal load relative to its neighbors;
- player inspects world geometry;
- Anchor unloads/releases the authored brace;
- mechanism/world responds physically.

Cantor does not auto-select the brace or fire Anchor.

### Manipulate → diagnose
Anchor changes access/load so a relationship can be measured honestly.

Example:
- Anchor removes a service cover or shifts a constrained assembly;
- an internal local field/load point becomes physically visible/readable;
- Cantor Listen can now focus it.

No through-wall diagnostic exception is granted before exposure.

### Establish relation → hold load
A Cantor Pattern may establish or certify a temporary local operational relationship, after which an Anchor brace can physically hold a mechanism within that now-known envelope.

The Pattern does not generate force; Anchor does not generate resonance authority.

### Hold load → perform procedure
Anchor may brace a moving/returning mechanism so Neris can safely perform a Cantor diagnostic/tuning procedure on another part of the same system.

The brace is ordinary one-brace authority; the Cantor procedure is ordinary pattern authority.

### Re-measure after physical change
Some problems require confirmation rather than one irreversible correct click:
- diagnose abnormal relation;
- change load;
- Listen again;
- determine whether relation is now stable, still conflicting, or changed in an unexpected but valid way.

This reinforces Neris as a repairer who verifies work rather than a spellcaster whose correct button automatically completes the state.

## Cantor Pattern boundary

A Cantor Pattern may change semantic resonance/operational state only according to its canonical procedure.

It may not generically:
- make an incompatible object Anchor-compatible;
- reduce arbitrary Anchor resistance as a hidden buff;
- reveal every Anchor target in a room;
- grant extra braces;
- extend Anchor range;
- suspend physics;
- solve a mechanism by matching the expected pattern name.

If a Pattern legitimately changes the underlying world relation such that an Anchor load point becomes available, that transition must be explainable from the Pattern's own effect and visible/IDE state.

## Anchor boundary

Anchor may not:
- tune Cantor patterns through cable tension unless a specific later canonical procedure explicitly measures tension as input;
- substitute physical force for a diagnostic procedure;
- make a false/unknown relationship become true simply by holding it in place;
- expose privileged history/meaning from a physical object;
- turn every resonant target into a pull point.

## Discovery philosophy

Synthesis should reward understanding, not inventory permutation.

The game should avoid rooms where the intended thought is:
> “I have two tools; I guess I use both because both icons are glowing.”

The desired thought is:
> “The measurement says the load is wrong. I can change load.”

Or:
> “I cannot measure the buried relation yet. I can physically expose it.”

Tool cues may confirm compatibility, but they may not advertise an exact two-step solution before the player has reasoned about the relationship.

## Progression and revisits

Combination content should deepen older verbs rather than invalidate them.

When a later Cantor Pattern unlocks, revisits may create new understanding of Anchor-visible structures. When a later Anchor mastery upgrade unlocks, it may create new physical arrangements that old Cantor procedures can diagnose.

Each unlock should make the player remember prior world relationships without turning old locations into icon checklists.

## Combat synthesis

Cantor + Anchor combat interactions remain tightly bounded.

Allowed structure:
- Cantor legitimately identifies a known operational/resonant condition on a visible component;
- Anchor physically changes that component/load under Decision #6;
- any enemy reaction remains Gate 2 authority.

Not allowed:
- scan enemy → automatic weak-point Anchor lock;
- pattern causes generic stun so Anchor can always remove armor;
- Anchor tension charges a magical damage burst;
- combo pauses enemies while the player performs a tool sequence.

## Accessibility

Synthesis must remain understandable without relying on:
- color-only cross-tool state;
- audio-only tuning distinctions;
- precision simultaneous button chords;
- rapid tool switching under tiny timing windows;
- remembering undocumented hidden pairings.

Relevant semantic states should be available through readable labels/cues, and known procedures should remain reviewable in the Cantor interface without revealing puzzle solutions.

## Comparative research boundary

Tears of the Kingdom demonstrates how several stable abilities can create emergent combinations across traversal, objects, and combat. Stillring adopts only the generic lesson that **separate verbs become richer when they operate on shared world state**. It does not copy ability switching, object construction, Recall behavior, Fuse behavior, UI, controls, or puzzle expression.

Unreal Engine 5.8 Gameplay Tags and Data Registries can support stable semantic IDs/capabilities and shared read-only configuration across systems. They are implementation options; cross-tool gameplay meaning remains explicit Stillring authority.

## Tool / Puzzle System IDE

### Inspect
Expose, side by side:
- Cantor diagnostic focus/state/pattern applicability;
- Anchor endpoint/load/brace state;
- shared semantic world facts each system is reading;
- which system last changed each relevant fact;
- derived eligibility transitions and reason;
- no hidden combo-state flag unless it merely summarizes already-visible facts.

### Exercise
Fixtures:
- diagnose → release brace;
- expose → diagnose;
- Cantor-established relation → Anchor hold;
- Anchor hold → Cantor procedure;
- physical change → re-measure;
- tempting but invalid resonant object that is not Anchor-compatible;
- Anchor-compatible object with no Cantor meaning;
- combat component requiring both systems through legitimate separate roles;
- reset from mid-synthesis.

### Validate
Catch:
- a combo-only hidden interaction bypassing both base contracts;
- Cantor changing Anchor range/brace count/force without explicit canonical procedure;
- Anchor exposing hidden semantic truth;
- objective metadata making a combination valid;
- pattern selector revealing the exact Anchor target;
- simultaneous-input requirement without accessibility alternative;
- reset leaving one subsystem's state stale relative to the other.

### Capture
Record cross-system causal timeline:
Cantor request/result → shared fact → Anchor request/result → world-state change → subsequent Cantor/Anchor eligibility → completion/reset.

## Locked statement

> **Cantor and Anchor combine by taking turns changing and reading the same honest world. There is no secret combo mode.**
